Clean Context Subagents agents/*.md, dispatchMode: "agent" ⚠️ Severe context bloat; tokens scale linearly with entire chat history.

How pipeline states are written atomically, stored in .sdlc/execution/, and auto-recovered after context compaction.

Ship State File JSON Schema

INSPECT SCHEMA 🔍

Stored in .sdlc/execution/ship-<branchSlug>-<timestamp>.json. Persists active release pipeline steps, flags, and review verdicts. 

{
  "branch": "main",
  "steps": [{ "id": "review", "status": "completed", "output": { "verdict": "approved" } }],
  "flags": { "preset": "full", "auto": false }
}

INSPECT SCHEMA 🔍

{
  "branch": "feat/new-auth",
  "waves": [{ "id": 1, "status": "completed", "tasks": [{ "id": "T1", "status": "completed" }] }]
}

Agent Dispatch & Context Lifecycle

Clean Context Architecture: How skills dispatch isolated subagents without sending chat history, forward context via manifests, and gather results.

1️⃣ Clean Context Isolation

Orchestrator agents defined in agents/*.md run in isolated context windows. They never inherit previous user chat turns.

2️⃣ Forward Manifest Passing

Skills serialize git diffs, project config, and task scopes into temporary manifest JSON files (.sdlc/tmp/*-manifest.json).

3️⃣ Backward Result Returning

Subagents return bounded string tokens (WAVE_SUMMARY) or write dedicated markdown files (review-comment.md).
